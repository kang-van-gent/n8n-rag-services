# ระบบ RAG ขั้นสูงพร้อมการแบ่งส่วนอัจฉริยะและการแยกผู้ใช้

## ภาพรวม

ระบบ RAG (Retrieval Augmented Generation) ขั้นสูงนี้ใช้การแบ่งส่วนเอกสารอัจฉริยะพร้อมการแยกผู้ใช้อย่างเข้มงวด เพื่อสร้างโซลูชันที่ฉลาด ปลอดภัย และขยายตัวได้

## คุณสมบัติหลัก

### 🧠 การแบ่งส่วนอัจฉริยะ
- **กลยุทธ์การแบ่งส่วนหลากหลาย**: แบ่งตามประโยค ตามย่อหน้า ขนาดคงที่ และการแบ่งตามความหมาย
- **การซ้อนทับอัจฉริยะ**: การซ้อนทับที่กำหนดได้ระหว่างส่วนต่างๆ เพื่อรักษาบริบท
- **การเคารพขอบเขต**: รักษาขอบเขตของประโยคและย่อหน้าเพื่อความสอดคล้องทางความหมายที่ดีขึ้น
- **การปรับขนาดให้เหมาะสม**: ขนาดส่วนที่กำหนดได้ซึ่งปรับให้เหมาะสมกับโมเดล LLM ต่างๆ

### 🔒 ความปลอดภัยและการแยกผู้ใช้
- **Row-Level Security (RLS)**: การแยกในระดับฐานข้อมูลที่ทำให้ผู้ใช้เข้าถึงได้เฉพาะข้อมูลของตนเอง
- **การตรวจสอบหลายชั้น**: การตรวจสอบการพิสูจน์ตัวตนในระดับบริการและฐานข้อมูล
- **การเข้าถึงส่วนข้อมูลแบบปลอดภัย**: แต่ละส่วนจะเชื่อมโยงกับ user ID เพื่อป้องกันการรั่วไหลของข้อมูลระหว่างผู้ใช้
- **การบังคับใช้นโยบาย**: นโยบายของ Supabase จะกรองข้อมูลตามผู้ใช้โดยอัตโนมัติ

### 📊 ข้อมูลเมตาที่หลากหลาย
- **สถิติส่วนข้อมูล**: การติดตามจำนวนคำ จำนวนประโยค ขนาดส่วนข้อมูล
- **การติดตามแหล่งที่มา**: เชื่อมโยงกลับไปยังเอกสารต้นฉบับและข้อมูลไฟล์
- **วิธีการแบ่งส่วน**: บันทึกอัลกอริทึมที่ใช้เพื่อความสามารถในการทำซ้ำ
- **ข้อมูลตำแหน่ง**: ออฟเซ็ตเริ่มต้น/สิ้นสุดสำหรับการสร้างเอกสารใหม่อย่างแม่นยำ

## วิธีการทำงาน

### 1. กระบวนการอัปโหลดไฟล์
```typescript
// ผู้ใช้อัปโหลดไฟล์
const result = await DocumentService.uploadAndProcessFile(file, userId, progressCallback);

// ระบบจะทำงานโดยอัตโนมัติ:
// 1. ตรวจสอบประเภทและขนาดไฟล์
// 2. แยกเนื้อหาข้อความ
// 3. อัปโหลดไปยัง storage bucket ที่ปลอดภัย
// 4. สร้างบันทึกเอกสารพร้อมการเชื่อมโยงผู้ใช้
// 5. แบ่งส่วนเนื้อหาอย่างอัจฉริยะ
// 6. จัดเก็บส่วนข้อมูลพร้อมข้อมูลเมตาครบถ้วนและการแยกผู้ใช้
```

### 2. กลยุทธ์การแบ่งส่วน

#### แบบตามประโยค (แนะนำ)
- รักษาขอบเขตประโยคเพื่อความสอดคล้องทางความหมายที่ดีขึ้น
- เหมาะสำหรับเอกสารข้อความและบทความส่วนใหญ่
- ขนาดส่วนเริ่มต้น: 1,000 ตัวอักษร (~150-200 คำ)
- การซ้อนทับ 20% เพื่อรักษาบริบท

#### แบบตามย่อหน้า
- รักษาโครงสร้างย่อหน้า
- เหมาะสำหรับเอกสารที่มีการแบ่งย่อหน้าชัดเจน
- รักษาการไหลของเอกสารตามตรรกะ

#### แบบขนาดคงที่
- การแบ่งส่วนตามขอบเขตคำแบบง่าย
- วิธีการสำรองสำหรับกรณีพิเศษ
- ขนาดส่วนที่สม่ำเสมอ

#### แบบความหมาย (ขั้นสูง)
- จัดกลุ่มเนื้อหาที่เกี่ยวข้องตามหัวข้อ
- การดำเนินการในอนาคตด้วยโมเดล NLP
- ปัจจุบันใช้วิธีตามประโยคแทน

### 3. สถาปัตยกรรมการแยกผู้ใช้

```sql
-- ทุกส่วนข้อมูลเชื่อมโยงกับผู้ใช้
CREATE POLICY "Users can only access their own chunks" ON document_chunks
    FOR ALL USING (auth.uid() = user_id);

-- การตรวจสอบในระดับบริการ
if (authCheck.userId !== userId) {
    return []; // ไม่อนุญาตการเข้าถึงข้ามผู้ใช้
}
```

### 4. กระบวนการสอบถาม RAG

```typescript
// เมื่อผู้ใช้สอบถามระบบ RAG:
const relevantChunks = await DocumentService.searchUserChunks(userId, query, limit);

// ระบบ:
// 1. ค้นหาเฉพาะส่วนข้อมูลที่ผู้ใช้เป็นเจ้าของ
// 2. ใช้การค้นหาความคล้ายคลึงของเวกเตอร์หรือการค้นหาข้อความแบบเต็ม
// 3. ส่งคืนส่วนข้อมูลที่เกี่ยวข้องตามบริบท
// 4. รักษาการแยกผู้ใช้อย่างสมบูรณ์
```

## โครงสร้างฐานข้อมูล

### ตารางเอกสาร
```sql
documents (
    id,
    user_id,        -- การแยกเจ้าของ
    content,        -- ข้อความเอกสารแบบเต็ม
    metadata,       -- ข้อมูลไฟล์ วันที่อัปโหลด ฯลฯ
    embedding,      -- embedding ระดับเอกสาร
    bucket_id       -- อ้างอิงการจัดเก็บ
)
```

### ตารางส่วนข้อมูลเอกสาร
```sql
document_chunks (
    id,
    document_id,    -- อ้างอิงไปยังเอกสารต้นทาง
    user_id,        -- สำคัญ: การแยกเจ้าของ
    content,        -- เนื้อหาข้อความของส่วน
    chunk_index,    -- ตำแหน่งภายในเอกสาร
    start_offset,   -- ตำแหน่งตัวอักษรเริ่มต้น
    end_offset,     -- ตำแหน่งตัวอักษรสิ้นสุด
    embedding,      -- เวกเตอร์สำหรับการค้นหาความคล้ายคลึง
    metadata        -- ข้อมูลเมตาของส่วนข้อมูลที่หลากหลาย
)
```

## คุณสมบัติความปลอดภัย

### 1. Row-Level Security (RLS)
- ฐานข้อมูลกรองข้อมูลตามผู้ใช้โดยอัตโนมัติ
- ป้องกันการเข้าถึงโดยไม่ได้รับอนุญาตในระดับฐานข้อมูล
- การบังคับใช้นโยบายสำหรับการดำเนินการ CRUD ทั้งหมด

### 2. การตรวจสอบในระดับบริการ
```typescript
const authCheck = await this.checkAuthentication();
if (!authCheck.isAuthenticated || authCheck.userId !== userId) {
    return []; // การปฏิเสธทันที
}
```

### 3. การป้องกันหลายชั้น
- การตรวจสอบการพิสูจน์ตัวตน
- การตรวจสอบ User ID
- การบังคับใช้นโยบายฐานข้อมูล
- การกรองในระดับการสอบถาม

## การปรับปรุงประสิทธิภาพ

### 1. การสอบถามที่มีดัชนี
```sql
-- การค้นหาเฉพาะผู้ใช้ที่รวดเร็ว
CREATE INDEX idx_document_chunks_user_id ON document_chunks(user_id);

-- การดึงส่วนข้อมูลเอกสารที่มีประสิทธิภาพ
CREATE INDEX idx_document_chunks_user_document ON document_chunks(user_id, document_id);

-- การค้นหาความคล้ายคลึงของเวกเตอร์
CREATE INDEX idx_document_chunks_embedding ON document_chunks USING ivfflat (embedding);
```

### 2. การแบ่งส่วนที่มีประสิทธิภาพ
- อัลกอริทึมที่ปรับให้เหมาะสมกับเนื้อหาประเภทต่างๆ
- พารามิเตอร์ที่กำหนดได้สำหรับการปรับแต่งประสิทธิภาพ
- การประมวลผลที่ใช้หน่วยความจำอย่างมีประสิทธิภาพสำหรับเอกสารขนาดใหญ่

## ประโยชน์สำหรับประสิทธิภาพ RAG

1. **บริบทที่ดีขึ้น**: การแบ่งส่วนอัจฉริยะรักษาขอบเขตความหมาย
2. **การดึงข้อมูลที่ปรับปรุง**: ขนาดส่วนที่เหมาะสมปรับปรุงคุณภาพของ embedding
3. **การซ้อนทับตามบริบท**: การซ้อนทับทำให้แน่ใจว่าบริบทสำคัญไม่สูญหาย
4. **การแยกผู้ใช้**: ฐานความรู้ที่ปลอดภัยและเป็นส่วนตัวสำหรับแต่ละผู้ใช้
5. **ความสามารถในการขยายตัว**: การสร้างดัชนีและการสอบถามที่มีประสิทธิภาพสำหรับคอลเลกชันเอกสารขนาดใหญ่
6. **ความยืดหยุ่น**: กลยุทธ์การแบ่งส่วนหลากหลายสำหรับเนื้อหาประเภทต่างๆ

## การผสานรวมกับ n8n

ระบบได้รับการออกแบบให้ทำงานร่วมกับเวิร์กโฟลว์ n8n ได้อย่างราบรื่น:

1. **การอัปโหลดเอกสาร**: เรียกใช้เวิร์กโฟลว์ n8n ผ่าน webhook
2. **การประมวลผลส่วนข้อมูล**: n8n ประมวลผลแต่ละส่วนสำหรับ embedding
3. **การจัดเก็บเวกเตอร์**: n8n อัปเดตฟิลด์ embedding ในฐานข้อมูล
4. **การประมวลผลการสอบถาม**: n8n ใช้ส่วนข้อมูลสำหรับการตอบสนอง RAG
5. **บริบทผู้ใช้**: การดำเนินการทั้งหมดรักษาการแยกผู้ใช้

ระบบขั้นสูงนี้เปลี่ยน RAG bot ของคุณจากเครื่องมือประมวลผลเอกสารธรรมดาให้เป็นระบบจัดการความรู้ที่ฉลาด ปลอดภัย และขยายตัวได้ซึ่งเคารพขอบเขตผู้ใช้ในขณะที่ส่งมอบประสิทธิภาพที่เหนือกว่า
